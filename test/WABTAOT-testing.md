# How to test AOT compiler functionality

## Compilation

To compile the runtime, compile the runtime environment using

```scripts/gitlab-build-aot.sh```

## Testing

Having a compiled aot executable under ./build/src/aot/wabtaot, run

```scripts/gitlab-aot-jit-test.sh```

for correctness testing.

## CI

Both the compilation and  test script are configured to be used with Gitlab-CI and should be executed automatically for compatible setups.
See .gitlab-ci.yml for details

## Testing methodology details

The output of jit-enabled wasmjit-omr available at [repo](https://github.com/wasmjit-omr/wasmjit-omr.git) at (Commit SHA: b358fba870105cf6170207058a00a7cfd2e9c8e3)interpreter is taken as the golden standard for AOT correctness verification.

### Files used for testing and their location

#### wasm tests

The WebAssembly text files used for testing can be found at:

``` test/jit/*.txt```

#### wasm objects

Due to evolution of the backbone of jit compiler, Eclipse OMR, the indicated version of wasmjit-omr is not compatible (at this moment), to be executed with AOT, which (WIP to fix that) means the standard WebAssembly (i.e interpreter, wat2wasm) tools cannot be compiled when AOT is enabled.
The workaround is to generate wasm binaries and carry them around with the testing commit, available by

``` test/jit/wasms/*.wasm```

#### pre-generated correct output

In future, the plan is to enable AOT and JIT coexistence and pipeline testing, but due to indicated incompatibility problem, the output (that is considered to be correct) can be found at:

``` test/jit/golden_results/*.out```

#### skip list

At this moment, the functionality of aot compiled code differs from interpreter+jit, needs some verification and fixing.
The problematic tests are excluded from executed for various reasons : compilation failure, compiled and loaded output mismatch, loaded and golden standard output mismatch.
The lists are available at:

* test\jit\golden_results\skip\compile_skip_list.txt
* test\jit\golden_results\skip\load_skip_list.txt
* test\jit\golden_results\skip\loaded_golden_skip_list.txt

#### Test failures description

For improved tracking, the

test\jit\golden_results\results_description.md

is suggested to be used.

### Output: understanding the testing results

The [script](#testing) generates a ./test-results/ folder with the following contents:

* A summary folder, that has all the failures
* All outputs generated by multiple executions
* Copies of golden outputs (To be replaced with output of the interpreter + jit version)
